# Retrudio — платформа по Arduino и робототехнике (Python / Flask)

Backend и frontend на Python: **Flask + Jinja2 + SQLite**. Каталог проектов берётся из папки `Schemes/`,
пользователи, избранное, комментарии и сохранённые схемы — в базе данных `data/app.db`.

## Запуск в VS Code

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows   (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env          # Linux/macOS: cp .env.example .env  → задайте SECRET_KEY
python app.py                   # http://127.0.0.1:5000
```

Название проекта меняется в одном месте: `PROJECT_NAME` в `.env`.

## Как добавить проект в `Schemes/`

Номер проекта = номер файла. Для проекта `4` создайте четыре файла:

| Файл     | Что внутри                                  |
|----------|---------------------------------------------|
| `4.png`  | картинка схемы                              |
| `4.json` | метаданные                                  |
| `4.txt`  | описание (на него ссылается `description`)  |
| `4.ino`  | код (на него ссылается `code`)              |

Минимальный `4.json` (как в вашем примере, но валидный JSON — ключи и значения в кавычках, запятые между полями):

```json
{
  "name": "Светодиод",
  "description": "4.txt",
  "free": true,
  "code": "4.ino"
}
```

Дополнительные необязательные поля: `board`, `category`, `difficulty` (`easy|medium|hard`), `components` (список),
`wiring` (список `{component, pin, board_pin}`), `warnings`, `steps`, `author`, `license`, `version`,
`changelog`, `dependencies`, `published` (`ГГГГ-ММ-ДД`), `verified` (`true` — только если автор реально проверил на железе).
`name`, `warnings`, `steps` можно задавать как `{"ru": "...", "uz": "...", "en": "..."}`;
`description` — как `{"ru": "4.txt", "uz": "4.uz.txt", "en": "4.en.txt"}`.
Категории: `robotics, smart_home, sensors, motors, wireless, iot, automation, displays, leds, measuring, education, advanced`.

Каталог перечитывается автоматически при изменении файлов — перезапуск не нужен.
Три демо-проекта (1–3) и их картинки-заглушки созданы для проверки; замените их своими
(`python tools/make_sample_images.py` пересоздаёт заглушки).

## Что реализовано

- Каталог с поиском, фильтрами (плата, категория, сложность, доступ, компонент), сортировкой и пагинацией.
- Страница проекта: схема, компоненты, таблица подключения, предупреждения, описание, шаги, код с подсветкой C++,
  копирование и скачивание `.ino`, комментарии с оценками (средняя оценка показывается только если оценки есть),
  избранное, похожие проекты, кнопка «Поделиться».
- Библиотека кодов: версии, лицензии, зависимости, журнал изменений.
- Конструктор схем (SVG): 16 компонентов, перетаскивание, провода с цветом, масштаб/сдвиг колёсиком,
  сохранение в профиль, публикация в «Сообществе». Breadboard в редакторе упрощён.
- Регистрация/вход (хэши паролей, CSRF-токены, HttpOnly-cookie), языки RU / UZ / EN.
- Платные проекты (`"free": false`): код и описание открываются только при активной подписке.

## Что нужно подключить самостоятельно

1. **Оплата подписки (FreeKassa).** Код готов, нужны только значения в `.env`
   (`FREEKASSA_SHOP_ID`, `FREEKASSA_SECRET1`, `FREEKASSA_SECRET2`, `SUBSCRIPTION_PRICE`, `SUBSCRIPTION_CURRENCY`).
   В кабинете кассы укажите (метод — **POST** для оповещения):

   | Поле в кабинете            | Значение                                   |
   |----------------------------|--------------------------------------------|
   | URL оповещения             | `https://ВАШ-ДОМЕН/payment/notify`         |
   | URL успешной оплаты        | `https://ВАШ-ДОМЕН/payment/success`        |
   | URL возврата при неудаче   | `https://ВАШ-ДОМЕН/payment/fail`           |

   Как это работает: кнопка «Оформить подписку» создаёт заказ в таблице `payments` и отправляет пользователя
   на страницу оплаты с подписью (Секретное слово 1). После оплаты FreeKassa вызывает `/payment/notify`;
   сервер проверяет подпись (Секретное слово 2), ID магазина и сумму, продлевает подписку и отвечает `YES`.
   Повторные оповещения безопасны. Страница «успешной оплаты» подписку **не** выдаёт.
   Адреса должны быть доступны из интернета по HTTPS (на `localhost` FreeKassa не достучится; для тестов — туннель вроде ngrok).
   **Проверка IP** включена по умолчанию (4 адреса серверов FreeKassa из их документации). Если сайт стоит за nginx,
   поставьте `TRUST_PROXY=1` и добавьте в конфиг nginx `proxy_set_header X-Real-IP $remote_addr;` — иначе сайт увидит
   адрес nginx и отклонит оповещения (в логе будет строка «IP … не в списке»). Для временного теста: `FREEKASSA_ALLOWED_IPS=none`.
   **Валюта** — только `RUB, USD, EUR, UAH, KZT` (список FreeKassa); узбекских сумов (UZS) нет.
   Адрес страницы оплаты по документации: `https://pay.fk.money/` (меняется в `FREEKASSA_PAY_URL`).
   Не хотите вписывать адреса вручную — укажите `SITE_URL` в `.env` и выполните `python manage.py payment-urls`:
   команда выведет три готовых адреса. Команда `python manage.py payment-check` отправит на ваш сайт тестовое
   подписанное оповещение (заказ 0, деньги и подписки не затрагиваются) и скажет, верны ли ID магазина и секретное слово 2.
   Валюту и способы оплаты уточните в настройках своей кассы. Вручную выдать подписку: `python manage.py grant-sub почта 30`.
2. **Донаты.** Укажите `DONATE_URL`; пока пусто — страница честно сообщает, что оплата не подключена.
3. **Продакшен.** `APP_ENV=production`, уникальный `SECRET_KEY`, HTTPS, запуск через
   `gunicorn app:app`, ограничение частоты запросов на `/login` и `/register` (например, nginx или Flask-Limiter),
   регулярные бэкапы `data/app.db`.

## Админ-аккаунты (для теста)

```bash
python manage.py create-admin adminrahmatulloh <пароль>
python manage.py create-admin adminodilxoja <пароль>
```

Вход — по username или email на странице входа. Администратору открыты все платные проекты. Повторный запуск меняет пароль.
Перед продакшеном смените пароли или удалите тестовые аккаунты.

## Тесты

```bash
python tests/test_app.py    # 60 проверок: каталог, безопасность, оплата FreeKassa; временная БД, тестовые ключи
```

## Ограничения

- Схемы, код и описания не проверяются автоматически. Демо-проекты не тестировались на реальном оборудовании
  (`verified: false`), и сайт показывает такую пометку. Не загружайте чужие работы без разрешения автора.
- Загрузки пользовательских изображений и админ-панели нет: проекты добавляются файлами в `Schemes/`.
- Роли модерации комментариев и публикаций пока нет.
